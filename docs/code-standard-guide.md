# 小刻食堂组开发流程与规范文档

## 📂 分支管理规范

### 1. 分支命名

| 分支类型   | 命名格式          | 使用场景说明                         |
| ---------- | ----------------- | ------------------------------------ |
| `feat/`    | feat/<功能简述>   | 新功能开发（例：`feat/user-login`）  |
| `hotfix/`  | hotfix/<修复简述> | 紧急线上问题修复                     |
| `release/` | release/<版本号>  | 预发布环境验证（例：`release/v1.2`） |
| `test/`    | test/<测试内容>   | 专项测试（如性能/压力测试）          |
| `docs/`    | docs/<文档内容>   | 文档更新（例：`docs/api-update`）    |
| `chore/`   | chore/<维护内容>  | 日常维护（依赖更新/代码优化）        |
| `config/`  | config/<变更类型> | 配置文件调整（需配套环境变量更新）   |

### 2. 分支策略

- `master` 分支受保护，​**禁止直接push**
- `dev` 合并自动部署，如遇到分支崩溃，删掉从主分支重新拉取（客户端可能没有这个分支）
- 新功能需从`master`创建分支开发

## ✨ 提交信息规范

- 使用 ​**Gitmoji** 开头（参考：[https://gitmoji.js.org/](https://gitmoji.js.org/)）
- 格式：`:emoji: 提交描述`  
  (例: `✨ 新增用户登录界面`)

## 🚀 环境与部署（后端与网页）

| 环境      | 部署方式                | 对应分支 |
| --------- | ----------------------- | -------- |
| 正式环境  | 通过手动打tag触发       | master   |
| 测试/开发 | 合并到dev分支后自动部署 | dev      |

## 🚨 部署前注意事项

- 如果新增项目**配置字段**, 群里联系将配置加入线上环境变量后再发布

### Tag使用规则

- 仅在`master`分支打tag（格式：`v1.0.0`）

## 🔀 代码合并流程

1. 本地开发 -> push到远端仓库
2. 创建Pull Request到master分支
   - 需至少1个Reviewer批准 ✅
   - 需通过所有Checker检查（CI/CD）
3. PR合并后自动：
   - 删除原分支 🗑️
